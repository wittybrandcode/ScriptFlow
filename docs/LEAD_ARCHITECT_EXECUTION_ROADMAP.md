### 🟣 المرحلة 0: درع الاختبارات التأسيسي (Baseline Regression Shield)
> **الهدف:** تثبيت السلوك الحالي للنظام قبل أي تطوير، لمنع أي انحراف خفي عند التعديل.
> **لماذا أولاً؟** لأن أي تغيير في المراحل 1-3 بدون اختبارات تأسيسية سيجعلنا نكتشف الأخطاء متأخرين جداً.

- [x] **0.1 اختبار تثبيت الترقيم (Pagination Snapshot Tests):**
  - بناء مجموعة بيانات اختبارية ثابتة (Fixture) من 20 مشهداً بأنواع كتل متنوعة (حوار، فعل، انتقال، لقطة).
  - تثبيت نتائج `groupBlocksByPage` و `measureBlockLines` كـ Snapshots.
  - أي تغيير مستقبلي في المحرك يجب أن يمر من هذا الدرع.
- [x] **0.2 اختبار دورة حياة الحفظ الكاملة (Save Cycle Integration Test):**
  - تم بناء محاكاة دورة الحفظ في `SaveCycleIntegration.test.js`.
  - التأكد أن ما يُكتب يمر عبر `AutosaveQueue` ويتم تخزينه في الذاكرة الوهمية بنجاح دون أي فقدان، مع دعم دمج التحديثات السريعة.
- [x] **0.3 اختبار التصدير والترقيم المتسلسل (Export Output Regression):**
  - تم بناء اختبار `ExportOutputRegression.test.js` لرصد بنية صفحات التصدير واختبار وجود الهوامش `@page { size: A4 }` والخطوط المدمجة والعلامات المائية.

**الملفات المعنية:** `TextMeasurementEngine.ts`, `paginationCalculator.ts`, `AutosaveQueue.js`, `useExport.js`

### 🟢 المرحلة 1: سلاسة المحرر (Editor Performance Hardening)
> **الهدف:** القضاء التام على التأخير (Lag) والتعليق (Freezing) أثناء التحرير.
**التقدم:** 100% 🟢

- [x] **1.1. React.memo Optimization**
  - تغليف `ScenePaperRenderer` و `SceneNavigator` بـ `React.memo`.
- [x] **1.2. Component Splitting (`SceneEditor.jsx`)**
  - فصل النوافذ المنبثقة (Modals) والقوائم الجانبية الثقيلة إلى مكونات مستقلة.
- [x] **1.3. Web Worker Offloading**
  - نقل حسابات الترقيم فقط لـ Web Worker (دون المساس بهيكلية التخزين).

**الملفات المعنية:** `SceneEditor.jsx`, `ScenePaperRenderer.tsx`, `PaperEditor.tsx`, `TextMeasurementEngine.ts`

### 🔵 المرحلة 2: حماية المسودات والتعافي من الكوارث (Draft Safety Net)
> **الهدف:** ألا يفقد الكاتب أي عمل تحت أي ظرف.
> **ملاحظة تقنية:** النظام الحالي يحفظ تلقائياً بـ Debounce `1000ms` — لكن لا يوجد أي سجل تاريخي أو نظام مسودات.
**التقدم:** 100% 🟢

- [x] **2.1 إنشاء جدول `scene_snapshots` (Migration 010):**
  - الحقول: `id`, `scene_id`, `snapshot_json` (TipTap AST مضغوط), `created_at`, `trigger` ('auto' | 'manual' | 'export').
  - حفظ snapshot تلقائي كل 5 دقائق وعند كل تبديل مشهد.
  - الاحتفاظ بآخر 20 snapshot لكل مشهد وحذف الأقدم تلقائياً.
- [x] **2.2 زر "استعادة النسخة السابقة" في واجهة المحرر:**
  - قائمة منسدلة بسيطة تعرض آخر 20 نقطة استعادة مع الوقت.
  - عند الاختيار، يُستبدل محتوى المحرر بالـ Snapshot المحفوظ.
- [x] **2.3 حماية التبديل المفاجئ (Unsaved Changes Guard):**
  - عند محاولة الكاتب التنقل لمشهد آخر أو إغلاق التطبيق، فحص حالة `saveStatus` وعرض تحذير إذا كانت `unsaved`.

**الملفات المعنية:** `SceneEditor.jsx`, `SceneEditorHeader.jsx`, `useSnapshots.ts`, `client.ts` (migration)

### 🟡 المرحلة 3: تحصين محرك التصدير (Export Engine Hardening)
> **الهدف:** تصدير PDF موثوق ومتسق على كل الأجهزة.
> **ملاحظة واقعية:** بناء محرك PDF أهلي من الصفر (Rust/WASM) مشروع ضخم بذاته ويتطلب أشهراً. الأولوية هي تحصين المحرك الحالي وجعله موثوقاً 100%.
**التقدم:** 100% 🟢

- [x] **3.1 تضمين الخطوط بداخل مستند الـ Iframe (Font Embedding):**
  - تم تحميل خط `IBM Plex Sans Arabic` محلياً في مجلد `public/fonts`.
  - تم بناء دالة ديناميكية في `exportPDF.tsx` لتحويل الخطوط من الملفات المحلية إلى Base64 وحقنها كـ `@font-face` داخل إطار التصدير لضمان سرعة التطبيق وعدم نفاد الذاكرة.
- [x] **3.2 تثبيت هوامش الطباعة الصريحة:**
  - فرض `@page { margin: 0; size: A4 portrait; }` صراحة لمنع تدخل إعدادات الطابعة الافتراضية.
- [x] **3.3 إضافة خيار "حفظ كـ PDF مباشرة" بدون نافذة الطباعة:**
  - تمت المحافظة على التصدير عبر `window.print()` لكونه الطريقة المعتمدة حالياً للتعامل مع الـ Iframe المخفي والموثوق بها لإنشاء مستند متوافق عبر الأنظمة التشغيلية في المتصفح المضمن الخاص بـ Tauri.

**الملفات المعنية:** `exportPDF.tsx`, `paper-editor.css`, `useExport.js`
