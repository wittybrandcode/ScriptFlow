# 💾 طابور الحفظ التلقائي وإدارة الحالة (05: Autosave & State Management)

يهدف هذا المستند إلى شرح كيفية إدارة حالة التطبيق (State) وحماية بيانات الكاتب من الضياع عبر آلية الحفظ التلقائي الصارمة.

## 1. طابور الحفظ (AutosaveQueue)
في الملف `apps/desktop/src/utils/AutosaveQueue.js` يتواجد الصنف المسؤول عن موازنة تدفق البيانات العالي القادم من لوحة المفاتيح نحو قاعدة البيانات SQLite.

### أ. ميكانيكية الـ Debounce
بدلاً من إرسال كل حرف يُكتب مباشرة إلى قاعدة البيانات، يستعمل الطابور مؤقتاً زمنياً (Debounce Timer):
- **المهلة الأساسية:** 1000 مللي ثانية (ثانية واحدة).
- يجمع الطابور الكتل المُعدلة طوال هذه الثانية. وإذا توقف الكاتب عن الكتابة لمدة ثانية، يتم تجميع البيانات (Batching) وإرسالها دفعة واحدة إلى `ScriptBlockRepository` ليتم حفظها باستخدام معاملة (`Transaction`).

### ب. قفل الحفظ المتسرع (Throttle Lock)
لضمان عدم تجاهل المهلة أثناء امتلاء الطابور، يمتلك `AutosaveQueue` قفلاً صراماً `if (this.queue.length > 0 && !this.timer)` يمنع إرسال البيانات بشكل متسرع، مما يضمن تدفقاً سلساً للمعاملات دون إغراق جسر IPC بين Tauri و React.

## 2. سياسة إعادة المحاولة (Exponential Backoff & Retry)
في البيئات المتزامنة العالية، قد تُغلق قاعدة البيانات مؤقتاً بسبب استعلام آخر (SQLITE_BUSY). 
يُعالج الطابور هذا الأمر عبر سياسة الاستعادة التراكمية (Retry Logic):
- المحاولة الأولى بعد 500 مللي ثانية.
- المحاولة الثانية بعد 1000 مللي ثانية.
- المحاولة الثالثة بعد 2000 مللي ثانية (2 ثانية).
هذا يضمن أن التعديلات ستُكتب في النهاية دون ضياع بيانات أو التسبب في انهيار (Crash).

## 3. حماية البيانات الصارمة (Force Flush)
لحل مشكلة "الضياع الصامت للبيانات" عند الإغلاق المفاجئ للتطبيق أو الانتقال السريع لمشهد آخر قبل انتهاء مهلة الـ 1000 مللي ثانية، تم تطبيق دالة إنقاذ صريحة تُدعى `flush()`:
- **دالة التفريغ الإجباري (`flush`)**: تقوم هذه الدالة بتنفيذ وكسر مؤقت الـ Debounce، وتمرير ما بقي من المهام في الذاكرة لتُنقش فوراً على القرص.
- **الاستدعاء الفعال:** يُستدعى `flush()` حصرياً وقائياً عند: إغلاق واجهة المستخدم، التصدير إلى PDF، أو تغيير مسار التوجيه (Route Navigation) للانتقال لسيناريو آخر.

## 4. الموفر التفاعلي (useSceneEditorState)
يربط الملف `useSceneEditorState.ts` بين المحرر البصري ومُشغل طابور الحفظ، مُحدثاً React Context بكل كتلة تتغير بفضل `activeScenarioId` وموفراً طبقة وساطة تنزع الحمل الثقيل عن كاهل المكونات.
